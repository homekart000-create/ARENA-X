# Frontend Authentication Migration: Phase 1

The static frontend now uses the Step 19 cookie-session API for login, registration, logout, and session checks. Configure the API base before `js/api.js` loads with `globalThis.ARENA_API_BASE_URL` or a `<meta name="arena-api-base-url" content="...">` element. When unset on a localhost HTTP development site, the client uses the local backend at port 3000; elsewhere it uses relative `api/...` requests, appropriate only when the static site and API share an origin/path. Remote API URLs must use HTTPS. Do not set a production URL until the backend has a real HTTPS deployment.

GitHub Pages currently serves only static files; it does not proxy `/api` requests. With the default empty base, authentication therefore reports the backend as unavailable on the current Pages deployment. When the API is deployed, set `API_BASE_URL` to its real HTTPS origin and add the exact GitHub Pages origin to the backend `CORS_ORIGINS`. The API must allow credentialed CORS and production cookies must retain the backend's `Secure`, `HttpOnly`, and `SameSite=None` settings. Browser third-party-cookie restrictions should be evaluated; a same-site API host is preferable where possible.

The browser never reads or stores the session cookie. Authenticated and protected pages check `/api/auth/me`; protected pages wait for that result and fail closed if the session cannot be verified. Login and signup forms defer their initial session check until the user submits a request, then verify the resulting cookie session through `/api/auth/me`. The server controls session lifetime; the former local “remember me” behavior is not retained.

The current-user responses from `/api/auth/me` and `/api/users/me` include the backend's role and active status, but no credentials or session token. The frontend keeps those authorization fields in memory only and requires an active backend session before granting admin UI access. Local role/status values are discarded from the auth cache and cannot grant access.

On load, the frontend removes password, password-hash, and session-token fields from records in `arena-x-users-v1`, and removes the legacy `arena-x-session-v1` entry. Other keys and competition/team/match/wallet data are left in place and are not migrated. A verified public user profile may be cached in the existing users key for local domain compatibility; role, status, demo flags, and credentials are not copied into that cache. If browser storage is unavailable, legacy credential cleanup cannot be guaranteed.

The frontend remains plain HTML/CSS/JavaScript with no Node runtime or build step. The existing service worker and static GitHub Pages layout are unchanged.
